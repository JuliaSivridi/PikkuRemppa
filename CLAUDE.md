# PikkuRemppa

Трекер домашних ремонтов для финского рынка. Одностраничное приложение, хостится как статика на
GitHub Pages, без бэкенда и БД — все данные хранятся в localStorage браузера.

Репозиторий: https://github.com/JuliaSivridi/PikkuRemppa (публичный — нужен для бесплатного GitHub
Pages для приватных репо нет).
Живой сайт: https://juliasivridi.github.io/PikkuRemppa/

## Стек

- React + TypeScript + Vite
- Zustand (`src/store/store.ts`) с `persist` middleware — вся država приложения в одном сторе,
  сохраняется в localStorage под ключом `pikkuremppa-data`. Версия схемы (`version: 2`) и
  `migrate()` в конфиге persist — при следующем изменении формата данных бампать версию и
  дописывать миграцию, а не просто менять типы.
- Стилизация — обычный CSS (`src/App.css`, `src/index.css`), без CSS-in-JS и без UI-библиотек.

## Деплой

GitHub Actions (`.github/workflows/deploy.yml`) собирает и публикует на Pages при пуше в `main`.
Ручных шагов нет — закоммитили, запушили, через ~30 сек сайт обновился. Смотреть статус:
`gh run list --repo JuliaSivridi/PikkuRemppa --limit 1`.

`vite.config.ts` — `base: '/PikkuRemppa/'`, завязано на имя репозитория.

## Язык интерфейса

Весь UI на финском. Ремонт называется по-фински «remontti», материал — «materiaali». Тексты для
пользователя (лейблы, кнопки, сообщения об ошибках) — только финский, комментарии в коде и коммиты
— английский.

## Модель данных (`src/types/index.ts`)

- `Repair` — ремонт: дата, `roomId`, `statusId`, `priorityId?`, `executor?` (self/service),
  описание, `cost` (**это стоимость только работы**, не общий итог — см. ниже).
- `Material` — материал, привязан к `repairId` и `categoryId`, произвольные `fieldValues`
  (набор полей задаётся категорией), `includeInTotal?` (default true).
- `Room`, `Status`, `Priority`, `MaterialCategory` — настраиваемые пользователем списки
  (Settings), не хардкод. У `Room` есть `colorIndex` для цветного индикатора.
- Общая стоимость ремонта — **не поле**, а вычисляемое значение:
  `repairTotal = repair.cost + Σ(material.price для материалов с includeInTotal !== false)`
  (`src/utils/cost.ts`). Так можно оставить `cost = 0` для работы, сделанной своими руками, и
  итог соберётся только из материалов.
- Правки задним числом пока не поддержаны — есть только добавление и удаление целиком
  (ни ремонт, ни материал нельзя отредактировать после создания). Это сознательное ограничение
  MVP, из-за него чекбокс `includeInTotal` можно выставить только при добавлении материала.

## Цветовая система (`src/utils/colors.ts`)

Три визуально разных семейства цветов, чтобы теги не сливались:
- **Комнаты** — 10 приглушённых (низкая насыщенность) оттенков по кругу, `roomColor(colorIndex)`,
  пользователь может переключать цвет комнаты кликом по кружку в настройках.
- **Статусы** — фиксированный набор из 4 холодных тонов по индексу в списке, `statusColor(index)`.
- **Приоритеты** — градиент «светофор» зелёный→жёлтый→красный по возрастанию важности,
  `priorityColor(index, total)`, не хардкод конкретных цветов под конкретные названия.

## Адаптивность (Remontit)

Ремонты рисуются дважды — таблицей (`RepairsTable.tsx`) и карточками (`RepairCard.tsx`) — с одним
и тем же отфильтрованным списком, а какая версия видна решает чистый CSS-медиазапрос на 860px
(`.repairs-list--mobile` / `.repairs-table-wrap` в `App.css`). JS для переключения не участвует.
Фильтры (поиск, диапазон стоимости, теги по комнате/статусу/приоритету) — не постоянная боковая
панель, а модалка по кнопке «Suodattimet» (тот же UX и на телефоне, и на десктопе).

## Парсинг ссылок на товары (`src/lib/linkParser/`)

«Киллер-фича» — вставить ссылку на товар из магазина и получить название/цену/категорию
автоматически. Технические детали важны, потому что решение уже дважды приходилось переделывать:

- Прямой `fetch()` на сайт магазина невозможен — CORS. Используется `r.jina.ai` (Reader API)
  как посредник: он сам сходит на сайт и отдаёт HTML с нужными CORS-заголовками.
- Публичные CORS-прокси (`corsproxy.io`, `allorigins`, `corsfix`) все оказались нерабочими на
  практике (платный ключ, вайтлист доменов, недоступность) — не возвращаться к ним без причины.
- Двухфазная загрузка: сначала быстрый `fetch` (работает для сайтов с серверным рендером —
  k-rauta, biltema, motonet, puuilo), и только если в HTML не нашлось `Product` JSON-LD/OG —
  повторный запрос в режиме markdown-ридера Jina (без спецзаголовков — они с `X-Wait-For-Selector`
  оказались ненадёжными, см. коммит истории). Для этого второго прохода данные достаются из текста
  регуляркой (`parseProductFromMarkdown`), т.к. DOM недоступен.
- Biltema — особый случай: JSON-LD добавляется через JS уже после загрузки, но сырые данные лежат
  в `window.productData` прямо в HTML — есть отдельный извлекатель `parseBiltemaProductData`.
- Категория подбирается из хлебных крошек (`parseBreadcrumbs` + `suggestCategoryFromBreadcrumbs`),
  создаётся автоматически, если подходящей нет. Из-за этого одинаковый товар в разных магазинах
  может уйти в разные категории — молча создавать новую не пытались чинить эвристиками, вместо
  этого в Settings есть инструмент «Yhdistä kategorioita» (слияние двух категорий вручную).
- Это всё равно best-effort: сайты меняют защиту от ботов, Jina меняет поведение кеша — если
  парсинг сломается для конкретного магазина, разбираться заново эмпирически (открыть страницу в
  браузере, посмотреть JSON-LD/breadcrumbs напрямую), а не гадать.

## Возможное будущее направление

Обсуждали вынос парсинга в отдельный сервис (Python/FastAPI + Playwright, сайт-специфичные
парсеры), чтобы не зависеть от стороннего Jina. Осознанно отложено — на этапе MVP не хотим
разворачивать и поддерживать ещё один сервер. Если/когда решим вернуться — см. историю разговора
про альтернативы стека.

## Локальная разработка

```bash
npm install
npm run dev       # или через Browser-превью в Claude Code (.claude/launch.json)
npm run build      # tsc -b && vite build — гонять перед каждым коммитом
```

Тестовые данные — `src/data/seed.ts`, применяются на пустом localStorage или через кнопку
«Palauta esimerkkitiedot» в настройках. При ручном тестировании в браузере не забывать
`localStorage.clear()` перед проверкой сценария «первый запуск».
